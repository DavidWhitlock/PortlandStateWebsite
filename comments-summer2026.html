Being able to use tools to overlay a very accessible UI over a backend felt like one of the missing puzzle pieces to building a full program that hadn't really been gone over in previous classes.
    • TDD and red-green refactoring! Last time I really got into TDD was with Chris Gilmore. 
    • I think that the importance of testing was one of the biggest concepts that I learned in this class. I have previously done some API and learned POST concepts as well as some Java. However, the use of integration testing and unit testing was both incredibly helpful and something that was a lot newer to me outside the use of Pytest suites. 
    • One of the most important things I have learned in this course is that time management is crucial to your success in this course and other courses in the upper division. While the projects might seem simple at first glance, they have a lot more complexity when you actually begin to code them, and you might run into issues that hinder your progress. It is very important to start your work ahead of time, especially during the summer term, since you don't get as much time to work on things as you think you do. If you're struggling with an assignment or a concept, make sure to reach out to you, the professor, and others in the course to help you through Slack or email so that you don't stay stuck and confused. Additionally, read the lecture notes and the accompanying videos ahead of time before you attend lecture, and make sure to attend every lecture so that you don't fall behind on the course content and can get questions answered in real time if you have them. Also, make sure to write tests as you're implementing your projects so that you always have high code coverage and know that your code is working as intended. I think those are the most important lessons that I have learned throughout this course, other than the programming knowledge that I have gained. 
    • The most valuable thing I learned in this course was how to design and develop software using object-oriented programming principles. I also improved my skills in pair programming, unit testing, and breaking complex problems into smaller, manageable tasks, making it easier to build and maintain applications.
  4. If you could give one piece of advice to someone taking this course in the future, what would it be?
    • That they're not only here to learn Java, but also to learn a bunch of other skills needed to be a successful software engineer. If you go in laser-focused on learning java/android development then you might miss out on or disregard a lot of other really important concepts that are taught in the course.
    • I would say try to attend all the mob programming and pair programing session.
    • brush up on java syntax and install Intellij
    • Be prepared to attend the required mob and peer programming sessions, and if you're taking this course over the summer be prepared for about 8-12 hours of coding (at least) per week on the assignments.
    • Start on P4 in parallel with P3. They cover the same things but starting at that point and developing the REST and SERVELET interfaces in parallel may be a lot easier than having to refactor later on.
    • I would tell them to stay on top of the course work and although it's fast-paced, try writing programs on your own time to get used to the syntax before the class picks up. I would also say to make sure to read the extra materials before the class begins and to have a solid POA before beginning the project. 
    • My advice is very similar to the question I answered above (Question 3). I think the most important piece of advice is to manage your time well when taking this course; do not start your projects at the last minute, ask questions if you're stuck, and always attend lectures because there is a lot of valuable information you'll learn that you wouldn't have if you'd just read the lecture notes and watched the pre-recorded videos. This might not apply to a non-summer term, but since there was overlap between projects due to a shorter term, start the next project even if you haven't finished the previous one because it'll take more time than you think to finish, so it is a good idea to get a head start on the future project even if you're not done with the previous one. Other than that, have fun and enjoy the course content because you'll learn a lot of valuable information that you might not have come across in previous courses.
    • Begin the projects as early as possible and stay on top of the coursework. Review object-oriented programming concepts before the class starts, ask for help when needed, and make the most of pair programming to learn from others. Consistent effort throughout the course will make the assignments much easier to complete.
