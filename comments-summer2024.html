  4. If you could give one piece of advice to someone taking this course in the future, what would it be?
    • Maybe just to keep an open mind and not overthink it too much, Java is a lot more intuitive than C++ and provides you with more flexibility. A lot of patterns you would struggle to implement in C++ are easy in Java. So keep an open mind and don't try too hard, realize that Java is actually easy. Also, I'd recommend people use the hell out of IntelliJ and get good at it throughout this course, as well as brush up on their Git skills before diving into this course.  IntelliJ was basically the backbone of my whole build pipeline and testing and coverage. I used the internal verify mvnw functions and site functions sometimes, particularly when testing for -Pgrader, but using Maven through the IntelliJ GUI and running coverage checks gives you a lot of nice, easy to use info. For instance, when you run coverage with Intellij, it literally highlights which lines still need to be covered right in your editor.
    • Just start, start small. I got so worried about thinking about how difficult the class would be and ended up procasinating really hard. Once I started really reading the documents and sjusst begin to write any code, I became relaxed and more eager to work on it.
    • Dont procrastinate
    • Be prepared for each class/lecture, the materials are really helpful for better understanding the lecture content and to follow the instructor's pace. And doing reviews after class is a great way to master the knowledge and information you learn from the class. 
    • For some people, it might be helpful to know that the programming assignments all build on each other and that you can't really not do one or do it poorly since you'd have a harder time further down the line. 
    • You can never have enough tests. I would spend hours trying to cover the edge cases, yet in most of my assignments there was still a point or two deduction because of failed test cases. I think it's also important to focus on the quality of the tests, rather than the quantity.

It should be part of CS 161 or 162, not something a professor has to cover because they can't be sure that students have learned it yet or not, every single term.
